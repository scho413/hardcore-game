### 1.1 지금 들어가 있는 그림 (2026-11-07 적용)

그림은 `src/assets/art/` 폴더 아래에 있어요. 코드 연결은 `src/art/hd.ts` 한 곳에 모여 있습니다.

| 폴더 | 내용 | 게임에서 쓰는 곳 |
|---|---|---|
| `monsters/` | 탑 몬스터 34종, 256×256, 배경 투명 | 전투, 탑 화면, 도감, 던전 목록, 이야기. 텍스처 키 `unit-<id>` |
| `bgs/` | 탑 배경 10장 + 기지 배경 3장, 424×632, 배경 불투명 | 전투 배경 (구간 5장 + 보스 방 5장), 기지 배경 (`bg-castle_1~3`, 숙소 Lv1~3 / 4~6 / 7 이상) |
| `buildings/` | 시설 6종 × Lv1~10 + `bld-lot`(빈 터) + `bld-scaffold`(공사 중) | 기지 마을, 시설 창 |
| `weapons/` | 직업 5개 × common/fine/superior (= 재료 단계 1/2/3). 기사는 방패와 검을 따로 | 무기 아이콘. 등급(일반~초월)은 뒤의 빛 색으로 구분 |
| `ui/advisor.png` | 안내자 기록관 오렌 (슬라임) | 이야기 마지막 장, 튜토리얼·도움말 대사창 얼굴 (`guideFace()`) |
| `consumables/` | 물약 7종 | 연금소. 기력 물약 = `potion_stimulant`, 치료 물약 = `potion_panacea`, 해독제 = `potion_antidote` |

**파일 이름 규칙**
- 파일 이름은 코드의 id와 같게 짓습니다.
- 다른 이름으로 올렸다면 `hd.ts`의 `MON_ALIAS`, `BLD_ALIAS`, `POTION_FILE`에서 연결합니다.
- 지금 걸려 있는 예외는 `goblin_hob` → `hobgoblin`, `goblin_wolf_rider` → `wolf_rider`, `smith_*` → `smithy` 입니다.

**크기 맞추기**
- 그린 그림은 예전 도트(16px)보다 커서, `fitScale()`이 예전 배율을 실제 배율로 바꿉니다.
- 몬스터마다 덩치가 다르기 때문에 `MON_SIZE`로 크기를 따로 줍니다. 그림은 모두 칸을 꽉 채우고 있습니다.
- 줄일 때는 밉맵으로 부드럽게 처리합니다 (`main.ts`의 `render.mipmapFilter`).
- 그림이 없는 것은 코드로 찍은 예전 도트가 그대로 나옵니다.
- **뭉개짐 방지:** 기지 건물과 전투 몬스터는 `resampled()`로 화면에 나올 크기에 맞춰 한 번 고품질로 줄인 뒤 1:1로 그립니다. 256px 도트를 실행 중에 0.69배처럼 애매한 배율로 줄이면 픽셀이 들쭉날쭉해지기 때문입니다.
- **전투 위치:** 발 위치를 배경 영역 높이의 비율로 정합니다 (`BattleScene`의 `ENEMY_FEET`, `ALLY_FEET`). 적은 안쪽 바닥, 영웅은 앞쪽 바닥에 섭니다. 아래쪽에 있는 유닛이 위에 그려집니다.

**기지 배치**
- `bg-castle` 그림 속 광장의 중심(424×632 기준 212, 355)을 기준점으로 씁니다.
- 건물 여섯 채는 `TownScene`의 `PLOTS`에 적힌 위치에 놓입니다.

### 1.2 만들어야 할 그림

모든 그림의 공통 규칙
- **배경은 반드시 투명.** 흰 배경으로 나오면 코드에서 지울 수는 있지만 테두리가 하얗게 남을 수 있습니다.
- **크기 선택:** 화면에서 크게 보이는 그림일수록 원본과 화면 크기가 비슷해야 선명합니다. 탑 배경은 424×632를 약 2배로 키워서 보여 주므로, 건물·몬스터를 256으로 만들면 배경보다 픽셀이 3배쯤 촘촘해 화풍이 조금 어긋납니다. 지금은 코드에서 고품질로 줄여서 맞추고 있습니다.
- 크기는 **256×256**, 배경 **투명 PNG**로 만듭니다. 배경 그림만 예외로 **424×632, 불투명**입니다.
- 이미 있는 그림을 PixelLab의 스타일 참고 이미지로 넣어서 화풍을 맞춥니다.
  - 몬스터 → `monsters/goblin.png`
  - 물약 → `consumables/potion_antidote.png`
  - 배경 → `bgs/goblin_cave.png`
- 정면 또는 살짝 비스듬한 정면, 서 있는 자세, 그림 하나가 칸 가운데를 꽉 채우게 만듭니다. 덩치 차이는 코드에서 줍니다.
- 파일 이름은 아래 표의 id를 그대로 씁니다.

#### A. 영웅 (2026-11-08 사용자와 확정)

목표는 **영웅마다 이름과 외형이 모두 다르게** 나오는 것입니다. 부위(머리·몸통·다리)를 따로 그려 조립하지 않습니다. AI로 따로 만든 부위는 각도와 비율이 달라 이음새가 어긋나기 때문입니다.

**1. 무엇을 정하나**
- **종족이 옷과 체형을 정합니다.**
  - 인간: 천 상의, 허리띠, 바지, 부츠
  - 바바리안: 털가죽, 맨팔, 문신
  - 엘프: 숲색 옷, 가벼운 가죽, 뾰족한 귀
  - 드워프: 쇠와 가죽, 땅딸막, 남자는 긴 수염
  - 수인: 동물 귀와 꼬리, 털 피부. 곰은 크게, 토끼는 가늘게
- **직업은 그림에 넣지 않습니다.** 코드가 `weapons/`의 무기 그림을 손에 얹어서 직업을 보여 줍니다. 기사는 검과 방패, 전사는 도끼, 궁수는 활, 마법사는 지팡이, 사제는 홀입니다. 만든 무기의 재료 단계에 따라 들고 있는 무기 모양도 바뀝니다.
- **다양성은 두 가지로 냅니다.** 같은 종족 안에서 버전마다 모양(머리 모양, 얼굴, 옷 디테일)을 다르게 그리고, 코드가 색을 바꿉니다(아래 4).

**2. 몇 장인가**
- 종족 8개 (`human`, `barbarian`, `elf`, `dwarf`, `rabbit`, `cat`, `dog`, `bear`) × 버전 2~3 × 성별 2.
- 사용자는 PixelLab의 **8방향 시트**(384×768, 칸 128×256, 3열 × 3행)를 성별마다 한 장씩 그대로 올립니다.
- 코드에서 쓰는 칸은 두 개입니다.
  - **앞모습:** 1행 1열 (0, 0). 카드, 도감, 대사창, 초상화에 씁니다.
  - **12시 방향 뒷모습:** 2행 2열 (128, 256). 전투에 씁니다. 영웅은 화면 아래에서 위쪽 적을 향해 서므로, 반듯한 뒷모습이 대열(전열·중열·후열)을 가장 잘 보여 줍니다. 뒤 대각선도 시험했지만 대열이 흐트러지고 방패 쪽 손이 가려져서 쓰지 않습니다.
- 파일 이름: `heroes/<종족>_<번호>_<m|f>.png` (예: `heroes/human_1_m.png`, `heroes/elf_2_f.png`)

**3. 그림에서 지킬 것**
- **배경 투명.**
- **자세:** 다리는 어깨너비, 팔은 몸 옆으로 조금 벌리고 주먹을 살짝 쥡니다. 손에는 아무것도 들지 않습니다. 모든 그림에서 손 위치가 비슷해야 해서, `human_1`을 스타일 참고 이미지로 계속 넣습니다.
- **앞뒤 일관성:** 앞모습과 뒷모습의 머리 모양, 망토, 장신구가 같아야 합니다. 시험 그림에서 여자가 앞은 땋은 머리, 뒤는 풀어 내린 머리로 나온 적이 있습니다.
- **얼굴이 보이게:** 투구, 두건, 가면은 쓰지 않습니다. 초상화는 앞모습에서 얼굴을 잘라 씁니다.
- **색 영역:** 머리카락, 피부(털), 옷 주색, 옷 보조색이 각각 한 계열 색이고 서로 확실히 달라야 합니다. 시험 그림처럼 노란 머리, 파란 옷, 빨간 허리띠, 회색 바지면 좋습니다.

**4. 코드가 할 일 (시험 끝남, 2026-11-08)**
- **자르기:** 시트에서 앞모습과 뒷모습 칸을 잘라 여백을 지웁니다.
- **손 찾기:** 몸통 아래쪽 높이에서 피부색 픽셀을 찾아 왼손과 오른손 위치를 구합니다.
- **무기 얹기**
  - 앞모습: 캐릭터 오른손은 화면 왼쪽이라 주무기를 그쪽에 둡니다. 무기를 몸 위에 그리고, 쥔 손을 다시 덮어 그려서 쥐고 있는 것처럼 보이게 합니다.
  - 뒷모습: 캐릭터 오른손이 화면 오른쪽입니다. 무기와 방패는 몸 뒤(화면 안쪽)에 그려서 몸이 가립니다.
  - 무기마다 쥐는 점(세로 비율)이 있습니다: 검 0.86, 도끼 0.78, 지팡이 0.62, 홀 0.72, 활은 가운데. 길이와 기울기는 직업별로 조정합니다.
- **색 바꾸기:** 색상(hue) 범위로 영역을 골라 다른 색으로 바꿉니다. 시험에서는 파란 옷(205~240°)과 노란 머리(30~55°)만으로도 충분히 다른 사람처럼 보였습니다. 실제로는 그림마다 영역 마스크를 미리 만들어 두고 `Look`의 색을 입힙니다. 겹치는 외형 검사는 지금처럼 `lookSignature`를 씁니다.
- **크기:** 전투에서 영웅 키는 약 140px입니다. 몬스터 덩치(`hd.ts`의 `MON_SIZE`)를 영웅 기준으로 다시 잡습니다.
  - 고블린류, 새끼 거미, 알: 영웅의 약 55%
  - 오크, 도적: 영웅 정도
  - 오우거, 트롤, 거인: 더 크게
  - 보스: 가장 크게
- **연결할 곳:** `src/art/textures.ts`의 `ensureHeroTextures()`(`hero-<id>`, `face-<id>`)를 바꿉니다. 전투(`BattleScene.createView`)는 뒷모습 텍스처를 쓰고, 나머지 화면은 앞모습을 씁니다.

**5. 진행 순서**
1. 사용자가 `human_1_m`, `human_1_f`를 올립니다.
2. Claude가 위 4번을 게임에 붙이고 미리보기로 보여 줍니다.
3. 확인되면 나머지 종족을 만듭니다.

#### B. 던전 (몬스터 11종 + 배경 3장)

던전은 3곳이고 각 10층입니다 (`src/data/dungeons.ts`).

| 던전 | 배경 파일 | 약한 적 | 강한 적 | 10층 보스 |

| 버려진 광산 `mine` | `bgs/dungeon_mine.png` | `slime`, `spider`(있음) | `troll`(있음) | `ogre` |

## 2. 광고·저장·출시 (그림 다음)
- 광고 SDK: 모집 광고 2회, 건설 단축, 동시 건설 2개. 지금은 누르면 바로 보상을 줍니다.
- 저장 안정화: 저장 손상 대비 백업 슬롯, 버전 이전 테스트.
- 테스트 모드 제거: 영웅 탭의 "테스트 모드"와 "인트로부터" 버튼, `window.__game`, `window.__tut`.
- 안드로이드 빌드, 구글 플레이 비공개 테스트.
